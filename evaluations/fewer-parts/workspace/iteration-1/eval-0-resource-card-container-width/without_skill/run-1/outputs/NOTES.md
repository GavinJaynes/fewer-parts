# Resource card - implementation notes

## What was implemented and why

Files changed (all inside the project directory):

- `index.html` - the resource card markup, five cards in total (two in the 300px sidebar, three in the 720px main column, one of which is the same resource as the first pinned card so both widths can be compared on one page), plus `min-w-0` on `<aside>` and `<main>`.
- `dist/output.css` - regenerated by `pnpm run build` (the file is git-ignored, but it is what the pages load).

No changes to `src/input.css`: the card uses only existing `@theme` tokens (`ink-*`, `paper-*`, `accent-600`) and stock Tailwind v4 utilities. No new runtime dependencies and no JavaScript.

### The card

```html
<article class="@container rounded-lg border border-ink-500/20 bg-white">
  <div class="grid gap-x-6 gap-y-2 p-4 @md:grid-cols-[minmax(0,1fr)_auto] @md:p-5">
    <h3 id="..." class="wrap-anywhere text-base font-semibold text-pretty hyphens-auto @md:col-start-1 @md:row-start-1 @md:self-baseline @md:text-lg">Title</h3>
    <p class="wrap-anywhere max-w-prose text-sm text-pretty text-ink-700 @md:col-start-1 @md:row-start-2 @md:text-base">Description</p>
    <p class="@md:col-start-2 @md:row-start-1 @md:self-baseline">
      <a href="..." aria-describedby="<title id>" class="inline-flex items-center gap-1 rounded-sm py-0.5 text-sm font-medium text-accent-600 underline decoration-accent-600/40 underline-offset-4 hover:decoration-accent-600 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent-600">Open resource <svg aria-hidden="true" ...arrow...></svg></a>
    </p>
  </div>
</article>
```

Decisions:

1. **Container queries, not viewport breakpoints.** The same card lives in a 300px column and a 720px column on the same page, so a viewport breakpoint cannot tell them apart. `@container` on the `<article>` makes the card lay itself out from the width it is actually given. Below Tailwind's `@md` container size (28rem / 448px, which sits between the two column widths) the title, description and link stack; at `@md` and up the link moves up beside the title on the same baseline and the type steps up one size (title 16 -> 18px, description 14 -> 16px, padding 16 -> 20px). Responsive utilities are on the inner `<div>` and its children rather than on the `<article>` itself, because an element cannot query its own size - only an ancestor container's. A useful side effect: below the `lg` breakpoint the page grid collapses to one column, and cards that were "sidebar" cards get the wide layout automatically because they are now wide.

2. **User content that cannot be trusted to wrap.** Both title and description use `wrap-anywhere` (`overflow-wrap: anywhere`) rather than `break-words` (`overflow-wrap: break-word`). The difference matters here: `anywhere` lets long URLs break at any character *and* those break opportunities count when the browser computes min-content width, so the card can never force a grid or flex column wider than it should be. `break-word` breaks the text visually but still reports the unbroken URL as the min-content width, which is exactly how a `1fr` column (the mobile layout) ends up wider than the viewport. `min-w-0` on `<aside>` and `<main>` and `minmax(0,1fr)` for the text column are belt-and-braces for the same problem. `hyphens-auto` on the title gives ordinary long words nicer break points (the page already has `lang="en"`), and `text-pretty` is a progressive enhancement for line breaking where supported.

3. **Quiet visual design.** White card, 1px `ink-500/20` border, no shadow, no hover lift. The only colour is the link, which is underlined (so it is not identified by colour alone) with a lighter underline that darkens on hover, and a small inline SVG arrow rather than a Unicode arrow so it renders the same in every font. Description line length is capped with `max-w-prose` in the wide layout so 720px cards stay readable. The focus style reuses the `focus-visible:outline-*` pattern already used on `contact.html`.

4. **Accessibility.** Each card is an `<article>` with a heading whose level fits its context (`<h3>` under the sidebar's `<h2>`, `<h2>` under the main column's `<h1>`). All links say "Open resource", so each carries `aria-describedby` pointing at its own title; screen readers announce the link followed by the title, which distinguishes the five identical link texts. The arrow icon is `aria-hidden`. The link has `py-0.5`, which brings it to 24px tall for touch (WCAG 2.5.8 minimum target size). Reading order in the DOM is title, description, link in both layouts; only the grid placement changes.

5. **Sample content.** Realistic library resources. The "2019 census microdata (offline mirror)" card contains a long unbroken URL in its description (`https://data.example.gov/statistics/census/2019/microdata/releases/v3/household-level-anonymised-extract-full.tar.gz`) and appears in both columns. The "Guidelines for the retention and disposal..." card in the sidebar has a long title.

## What was verified and how

Commands run:

- `pnpm run build` - succeeds; confirmed with `grep` that `dist/output.css` contains `container-type: inline-size`, `@container (width >= 28rem)`, `overflow-wrap: anywhere`, `-webkit-hyphens: auto; hyphens: auto`, and `text-wrap: pretty`.
- `python -m http.server 8819 --bind 127.0.0.1 --directory <project>` to serve the page. (A first attempt on port 8847 collided with another task's server on the same port - Windows let both bind - so that process was stopped and 8819, verified free with `netstat`, was used instead. `curl` confirmed 8819 served the new 10,465-byte `index.html` before any browser check.)

Browser checks (Chromium-based in-app browser pane, own tab):

- **1280x900 (two-column layout).** Measured via DOM: `<aside>` 300px, `<main>` 720px; sidebar cards 300px wide with a single grid column, title 16px, description 14px, link at the bottom; main cards 720px wide with grid columns `541px 113px`, title 18px, description 16px, link in the top-right on the title's baseline. Every card and every description reported `scrollWidth <= clientWidth`, and `document.documentElement.scrollWidth === clientWidth` (no horizontal page overflow). `container-type` computed to `inline-size` on every card.
- **375x812 (mobile preset).** Page stacks to one column; all cards 327px wide, one grid column, no overflow anywhere, link 24px tall. Screenshot confirmed the long URL wraps inside the card across three lines and the long title wraps to four lines cleanly.
- **768x1024 (tablet preset).** All five cards 705px wide and every one switches to the two-column layout with the link beside the title (including the two "sidebar" cards, since they are now wide), no overflow. Screenshot confirmed.
- Viewport emulation was reset to desktop afterwards and the server process was stopped.

Not verified: Firefox and Safari were not available in the pane, so the cross-browser claims below rest on the compatibility data cited rather than on hands-on testing. Keyboard focus styling was not exercised interactively; it uses the same utilities as the existing contact form.

## Browser-support claims and sources

Targets are current stable Chrome, Edge, Firefox and Safari, including iOS Safari and Android Chrome. Every feature used is well inside those targets:

| Feature | Chrome / Edge / Android Chrome | Firefox | Safari / iOS Safari | Source |
|---|---|---|---|---|
| `@container` size queries, `container-type: inline-size` | 105 | 110 | 16 | MDN `@container` page: "Baseline Widely available" since February 2023 (https://developer.mozilla.org/en-US/docs/Web/CSS/@container) |
| `overflow-wrap: anywhere` | 80 | 65 | 15.4 | mdn/browser-compat-data `css/properties/overflow-wrap.json` |
| `hyphens: auto` | 88 (Android 55) | 6 | 5.1 with `-webkit-` prefix, 17 unprefixed; Tailwind emits both | mdn/browser-compat-data `css/properties/hyphens.json`; MDN notes hyphenation needs a `lang` attribute and a dictionary for that language |
| `text-wrap: pretty` | 117 | not supported | 26 | mdn/browser-compat-data `css/properties/text-wrap.json` |

`text-wrap: pretty` is purely a progressive enhancement: where it is unsupported (Firefox) the declaration is ignored and text wraps normally; nothing in the layout depends on it. Everything else (`grid`, `gap`, `minmax()`, `min-width: 0`, `:focus-visible`, `inline-flex`) has been baseline for years.
